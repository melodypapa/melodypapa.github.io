## 1. 文档范围

本文档规定 **AUTOSAR** 诊断（**Diagnostics**）的系统需求。它不依赖于任何特定实现，包含面向 **AUTOSAR** 经典平台与自适应平台的公共基础需求，以及经典平台和自适应平台各自特定的需求。

在经典平台章节中，应实现对法规 OBD 和增强诊断的处理。诊断基础软件元素集合应尽可能地由汽车软件模块的既有元素组成。只有在有充分理由时，有效的软件元素才应成为该集合的一部分。此时这些有效元素的定义不属于本工作包的范围。尽管如此，关于额外所需基础软件元素的信息应提供给相关工作组。

在自适应平台章节中，有几条与自适应环境相关的约束需要注意：

- 仅提供以太网作为物理通信基础设施的支持，1.0 版本不计划支持其他典型总线通信；因此，本规范未考虑引用其他总线协议标准（如 J1939、**FlexRay**、**CAN** 等）的所有经典 **SRS** 诊断需求
- 由于关于 **AUTOSAR** 自适应平台将适用的汽车域的信息不足，**OBD** 协议（标准化为 ISO 15031）也不属于本规范的对象
- **AUTOSAR** 自适应平台 1.0 版本计划作为未来开发的学习环境，因此其接口以 ICC1（接口符合类，**Interface Conformance Class**）粒度级别描述，即不规定内部的 **DM** 接口

## 2. 缩略语和缩写

**CAN**
> 控制器局域网（**Controller Area Network**，通信总线）

**DEM**
> 诊断事件管理器（**Diagnostic Event Manager**）

**DID**
> 诊断标识符（**Diagnostic Identifier**）

**DM**
> 诊断管理（**Diagnostic Management**）

**DoIP**
> 基于 **IP** 的诊断——标准化为 ISO 13400 的诊断服务传输协议

**DTC**
> 诊断故障码（**Diagnostic Trouble Code**）

**ECU**
> 电子控制单元（**Electronic Control Unit**）

**IDL**
> 接口描述语言（**Interface Description Language**）

**OBD**
> 车载诊断（标准化为 ISO 15031）

**RTE**
> 运行环境（**Runtime Environment**）

**SA**
> 源地址（测试仪的诊断地址）

**SID**
> 服务标识符（唯一标识 **UDS** 服务的十六进制数），0x22 为按标识符读取数据服务，0x2E 为写入非易失性存储器服务

**SWC**
> 软件组件（可指经典平台 **SWC** 或自适应平台 **SWC**）

**TA**
> 目标地址（**ECU** 的诊断地址）

**UDS**
> 统一诊断服务，标准化为 ISO 14229

## 3. 所用约定

在需求中使用了以下特定语义：

本文档中的关键词 'MUST'、'MUST NOT'、'REQUIRED'、'SHALL'、'SHALL NOT'、'SHOULD'、'SHOULD NOT'、'RECOMMENDED'、'MAY' 和 'OPTIONAL' 应按如下方式解释。请注意，使用这些词语的文档的需求层级会修饰这些词语的强制力。

- **SHALL**：该词表示该定义是规范中的绝对要求。
- **SHALL NOT**：该短语表示该定义是规范中的绝对禁止。
- **MUST**：该词或术语 'REQUIRED' 或 'SHALL' 表示该定义是规范中的绝对要求。
- **MUST NOT**：该短语或短语 'SHALL NOT' 表示该定义是规范中的绝对禁止。
- **SHOULD**：该词或形容词 'RECOMMENDED' 表示，在特定情形下可能存在充分理由忽略某一事项，但在选择不同做法之前必须理解并仔细权衡其全部影响。
- **SHOULD NOT**：该短语或短语 'NOT RECOMMENDED' 表示，在特定情形下，某种特定行为是可接受的甚至有用的，但在实现以此标签描述的任何行为之前，应理解其全部影响并仔细权衡具体情况。
- **MAY**：该词或形容词 'OPTIONAL' 表示，某一事项是真正可选的。一个供应商可以选择包含该事项，因为特定市场需要它，或者因为该供应商认为它能增强产品；而另一个供应商可以省略同一事项。不包含某一特定选项的实现必须准备好与包含该选项的另一实现互操作（尽管功能可能有所减少）。同样，包含某一特定选项的实现必须准备好与不包含该选项的另一实现互操作（当然，该选项所提供的功能除外）。

### 4.1. 面向经典平台和自适应平台的通用诊断需求
