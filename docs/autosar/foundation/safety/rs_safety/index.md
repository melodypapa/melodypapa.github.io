## 1. 文档范围

本文档基于通过 **AUTOSAR_FO_RS_Main** [\[1\]](#ref-1) 提供的项目目标和高层安全需求，规定对 **AUTOSAR** 平台的安全需求。它使用了以下文档中所描述的预期功能：

- AUTOSAR_AP_EXP_PlatformDesign [\[2\]](#ref-2)
- AUTOSAR_CP_EXP_LayeredSoftwareArchitecture [\[3\]](#ref-3)
- AUTOSAR_AP_EXP_SWArchitecture [\[4\]](#ref-4)。

功能安全需求由 AUTOSAR_EXP_SafetyOverview [\[5\]](#ref-5) 中提到的顶层安全需求和危害导出。

本文档包含对 **AUTOSAR** 功能集群、服务和 **AUTOSAR** 基础软件模块的技术安全需求视图。这些需求从各自的目标需求规范中提取并包含在本文档中，以便读者在一篇文档中获得完整概览。

## 无 ASIL 等级

**AUTOSAR** 联盟，特别是 **AUTOSAR** 自适应平台工作组，仅提供架构定义、功能块描述和概念验证实现，因此如 **ISO 26262** [\[6\]](#ref-6) 中所述，无法为该范围内的任何需求添加 **ASIL** 等级。

## 2. 如何阅读本文档

本文档包含通用的功能安全需求，不提及 **AUTOSAR** 的具体解决方案/组件。技术安全需求随后从功能安全需求导出，并指明 **AUTOSAR** 组件的具体职责。每条需求都有其唯一标识符，以前缀 `RS_SAF_`（表示 "Safety Requirement"）开头。

技术安全需求部分提取自各目标组件需求规范，因此不带 `RS_SAF_` 前缀。并非所有技术需求都已完成整合，目标是让所有技术需求成为目标需求规范的一部分，此处收录它们只是为了形成一个完整的安全需求目录。

### 2.1. 文档约定

**AUTOSAR** 文档中需求的呈现遵循 TPS_STDT_00078 中规定的表格，参见标准化模板（**Standardization Template**）的「可追溯性支持（**Support for Traceability**）」章节（[\[7\]](#ref-7)）。

应使用 TPS_STDT_00053 中规定的表达义务的言语形式来表示需求，参见标准化模板的「可追溯性支持」章节（[\[7\]](#ref-7)）。

### 2.2. 所用约定

本文档中的关键词 "**MUST**"、"**MUST NOT**"、"**REQUIRED**"、"**SHALL**"、"**SHALL NOT**"、"**SHOULD**"、"**SHOULD NOT**"、"**RECOMMENDED**"、"**MAY**" 和 "**OPTIONAL**" 应按如下方式解释。

请注意，使用这些词语的文档的需求层级会修饰这些词语的强制力。

- **MUST**：该词或形容词 "**LEGALLY REQUIRED**" 表示，由于法律问题，该定义是规范中的绝对要求。
- **MUST NOT**：该短语表示，由于法律问题，该定义是规范中的绝对禁止。
- **SHALL**：该短语或形容词 "**REQUIRED**" 表示，该定义是规范中的绝对要求。
- **SHALL NOT**：该短语表示，该定义是规范中的绝对禁止。
- **SHOULD**：该词或形容词 "**RECOMMENDED**" 表示，在特定情形下可能存在充分理由忽略某一事项，但在选择不同做法之前必须理解并仔细权衡其全部影响。
- **SHOULD NOT**：该短语或短语 "**NOT RECOMMENDED**" 表示，在特定情形下，某种特定行为是可接受的甚至有用的，但在实现以此标签描述的任何行为之前，应理解其全部影响并仔细权衡具体情况。
- **MAY**：该词或形容词 "**OPTIONAL**" 表示，某一事项是真正可选的。一个供应商可以选择包含该事项，因为特定市场需要它，或者因为该供应商认为它能增强产品；而另一个供应商可以省略同一事项。

不包含某一特定选项的实现，应准备好与包含该选项的另一实现互操作（尽管功能可能有所减少）。同样，包含某一特定选项的实现，应准备好与不包含该选项的另一实现互操作（当然，该选项所提供的功能除外）。

#### 2.2.1. 需求标识符编码

安全需求的唯一标识符应由以下部分组成：

- 一个文档标识符
- 一个区分功能安全需求和技术安全需求的标识符
- 一个标识目标组件的标识符（**AUTOSAR** 自适应平台中的功能集群，或 **AUTOSAR** 经典平台中的基础软件组件）
- 一个需求编号

本需求规范中使用的编码模式为 `RS_SAF_<Z><YY><XX>`，其中

- Z 是一位数字，描述该需求是：
  - 0：安全目标或顶层安全需求，其中 YY 保留，XX 为两位数字
  - 1：**AUTOSAR** 自适应平台的功能安全需求，其中 YY 保留，XX 为两位数字
  - 2：**AUTOSAR** 自适应平台的技术安全需求，其中 YY 是两位数字，描述需求所针对的对象：
    - 00：保留
    - 11：平台健康监控（**PHM**）
    - 12：执行管理（**EM**）
    - 13：状态管理（**SM**）
    - 14：操作系统（**OS**）
    - 15：持久化（**PER**）
    - 16：通信管理（**CM**）
    - 17：更新和配置管理（**UCM**）
  - 3：**AUTOSAR** 经典平台的技术安全需求，其中 YY 是两位数字，描述需求所针对的对象：
    - 00：保留
    - 11：看门狗管理器（**WDGM**）
    - 12：操作系统（**OS**）
    - 13：**E2E** 保护（**E2E**）
  - 4–9：保留供将来使用

##### 4.3.3.2. 基础软件：操作系统（**OS**）

**应用的内存保护**

| 描述 | 操作系统应阻止应用在其分配的内存区域之外执行写访问。 |
| --- | --- |
| 理由 | 为了实现免受干扰，必须阻止应用对其他应用产生不利影响。为应用保留的私有内存的访问应受到保护，免受来自其他应用的未授权写访问。 |
| 用例 | 一个 **QM** 应用和一个 **ASIL** 应用在同一台机器上执行。**OS** 阻止 **QM** 应用更改分配给安全关键应用的内存。 |
| 适用平台 | **CP** |
| 依赖项 | **OSEK OS** |
| 支撑材料 | - |

**应用的时序保护**

| 描述 | 操作系统不得允许任何应用中的时序故障传播。时序故障可能由以下原因引起：<br>* 超出静态/预运行规定的执行时间预算<br>* 超出静态/预运行规定的阻塞时间预算<br>* 超出静态/预运行规定的到达速率 |

| 用例 | 一个 **QM** 应用和一个 **ASIL** 应用在同一台机器上执行。**OS** 阻止 **QM** 应用将其延迟传播到安全关键应用。 |

##### 4.3.3.3. E2E 保护

**使用 E2E 转换器和 E2E 库的 E2E 保护**

| 描述 | 通信服务、**E2E** 转换器和 **E2E** 库应通过考虑 **ISO** 标准中列出的所有故障（ISO 26262:6-2018 D.2.4），提供检测软件组件之间信息交换期间错误的机制。**E2E** 检查的结果需要发布给应用。如果使用 **E2E** 转换器，则需要按照与被转换的应用和数据相同的 **ASIL** 等级来开发 **RTE** 接口。 |
| --- | --- |
| 理由 | 创建此需求最初是为了通过提供安全措施和机制来实现 **AUTOSAR** 支持安全相关系统开发的目标。由于用户可能构建项目特定的应用，**AUTOSAR** 只能提供信息的安全交换。提及并应遵循 **ISO 26262**，因为它是汽车 **E/E** 系统功能安全的国际标准。 |
| 用例 | 不同控制设备上的两个 **ASIL** 等级应用应通过一个较低 **ASIL** 等级的组件（**HW** 或 **SW**）交换信息。**E2E** 转换器和 **E2E** 库应支持计数器、校验和时间戳等安全机制，使 **ASIL** 应用或 **E2E** 转换器和 **E2E** 库的实现能够检测并确保信息已被正确、及时且按序传输。 |
| 适用平台 | **CP** |
| 依赖项 | **E2E Library**、**E2E Transformer**、**RTE**、**SWC** |
| 支撑材料 | - |

**允许集成者配置用于检测通信故障的安全机制**

| 描述 | 基于各自的安全概念，通信服务、**E2E** 转换器和 **E2E** 库应允许集成者选择和配置用于检测通信故障的安全机制集。 |
| --- | --- |
| 理由 | 不同的通信总线和数据信息可能需要 **E2E** 提供不同程度的保护。因此，具有可配置性（部署前）是合理的，这样集成者就可以自由选择要部署的机制集。 |
| 用例 | 高层设计变更或新信息需要不同的通信保护机制。集成者可以通过更改清单（**Manifest**）来选择适当的保护。 |
| 适用平台 | **CP** |
| 依赖项 | **E2E Library**、**E2E Transformer**、**RTE**、**SWC** |
| 支撑材料 | - |
