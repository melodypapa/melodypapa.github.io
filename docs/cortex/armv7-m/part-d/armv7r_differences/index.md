本附录比较 **Armv7-M** 与 **Armv7-R** 体系结构配置文件，指出二者的相同点与差异。本章包含以下小节：

* 第 D5-798 页的**关于 Armv7-M 与 Armv7-R 体系结构配置文件**。
* 第 D5-799 页的**端序支持**。
* 第 D5-800 页的**应用级支持**。
* 第 D5-801 页的**系统级支持**。
* 第 D5-802 页的**调试支持**。

## 1. 关于 Armv7-M 与 Armv7-R 体系结构配置文件

**Thumb-2** 技术为所有 **Armv7** 配置文件所共有，**Armv7-M** 与 **Armv7-R** 配置文件之间还有其他重要的相同点。理解这些相同点与差异，开发者就能最大限度地减少在两种配置文件上支持软件、或构建可从一个配置文件直接迁移到另一配置文件的系统架构所需的工作量。

选择配置文件时必须做出的一项系统权衡是**绝对性能**与**中断延迟**之间的取舍。

## 2. 端序支持

**Armv7-R** 支持大端与小端格式的取指，格式由**系统控制寄存器**（**System Control Register**）中的 IE 位决定。**Armv7-M** 只支持小端格式的取指。若 **Armv7-M** 实现需要大端指令格式，则总线结构必须在半字内执行字节交换。字节交换仅用于取指，不得出现在数据访问上。

例如，对 32 位总线上的取指：

```arm
PrefetchInstr<31:24> -> PrefetchInstr<23:16>
PrefetchInstr<23:16> -> PrefetchInstr<31:24>
PrefetchInstr<15:8> -> PrefetchInstr<7:0>
PrefetchInstr<7:0> -> PrefetchInstr<15:8>
```

**Armv7-M** 与 **Armv7-R** 都支持可配置的数据访问端序模型，参见第 A3-67 页的**端序支持**。**Armv7-R** 通过其 xPSR 中的控制位与**系统控制寄存器**的 EE 位支持动态端序控制，而 **Armv7-M** 在复位时静态配置。

## 3. 应用级支持

在应用级，**Armv7-M** 可视为 **Armv7-R** 的子集。**Armv7-R** 支持 **Armv7-M** 的全部应用级指令，并使用相同的标志与通用寄存器。不过，**Armv7-R** 中的 **Load Multiple** 与 **Store Multiple** 指令总是可重启的（**restartable**），不支持基于 xPSR.ICI 位的 **Armv7-M** 重启模型。而特权软件的执行会暴露两种配置文件之间的系统级差异。

**Armv7-R** 的附加支持包括：

* **SIMD** 指令与饱和运算：
    * 基线 **Armv7-M** 配置文件只支持 `SSAT` 与 `USAT` 饱和指令。
    * **Armv7-M DSP** 扩展增加了对 **Armv7-R** 所支持的全部 DSP 指令的支持。
* **Arm** 与 **Thumb** 指令集以及二者之间的互工作。**Armv7-M** 仅支持 **Thumb**。
* 同步方面，**Armv7-M** 只支持字节、半字与字版本的加载和存储独占指令。**Armv7-R** 还支持这些指令的双字版本以及遗留的 **swap** 指令。

**注意：** 对所有体系结构配置文件，Arm 都反对使用遗留的 **swap** 指令。

**Armv7-R** 与 **Armv7-M** 都支持硬件除法指令 `SDIV` 与 `UDIV`。

**Armv7-R** 与 **Armv7-M** 都支持可选的**浮点扩展**（**Floating-point Extension**）。不过：

* **Armv7-R** 扩展包含 **Armv7-M** 不支持的双精度算子。
* **Armv7-M** 浮点扩展的体系结构要求比 **Armv7-R** 简单得多。特别是 **Armv7-M** 没有浮点子架构（**floating-point subarchitecture**）的概念，而 **Armv7-R** 实现要求该概念。

**注意：** **Armv7-R** 配置文件可以使用 NEON 技术支持 **Advanced SIMD** 扩展。**Armv7-M** 不支持 **Advanced SIMD**。

## 4. 系统级支持

两种配置文件的程序员模型与异常模型存在显著差异：

* **Armv7-R** 支持：
    * 一组运行模式，例如为每一类异常的处理提供专用模式。内核寄存器在不同模式之间是分组（**banked**）的。
    * 用于异常处理的固定入口点（地址）。处理异常时，压栈与出栈由软件控制。
    * 通过**系统控制协处理器**（**System Control Coprocessor**，**CP15**）接口进行控制与配置。
    * 通过 **CP14** 协处理器接口进行调试控制与配置。
* **Armv7-M** 只对栈指针分组。它使用专用寄存器与内存映射资源的组合进行系统配置与执行管理，无论正常操作还是调试都是如此。**Armv7-M** 的一项关键特性是低延迟异常处理，在异常进入与退出时自动压栈与出栈。

**Armv7-M** 浮点扩展提供可配置的浮点寄存器硬件压栈与出栈。

系统级指令支持不同，反映了不同的程序员模型。两种配置文件都支持 `CPS`、`MRS` 与 `MSR` 指令，但执行方式不同。**Armv7-R** 提供附加的系统级指令，例如 `SRS` 与 `RFE`。由于异常模型不同，**Wait For Exception** 与 **Wait For Interrupt** 的行为也不同。

两种配置文件都支持 **Arm 受保护内存系统架构**（**Protected Memory System Architecture**，**PMSAv7**）。它是：

* **Armv7-R** 中的必需特性。
* **Armv7-M** 中的可选特性。

**PMSAv7** 在两种配置文件中提供相同的特性。虽然寄存器访问机制不同，但寄存器布局大体相同。未支持或禁用 **PMSAv7** 时，两种配置文件都有默认内存映射。两种默认内存映射都把内存划分为具有不同属性的区域，划分方式类似，但映射并不完全相同。

异常模型不同，意味着两种配置文件在 **PMSA** 错误处理上存在一些差异。

**Armv7-R** 面向更高性能（更高时钟频率）的器件，并包含对紧耦合（**closely coupled**）缓存的支持。**Armv7-M** 支持内存映射的系统缓存，对紧耦合缓存只有有限支持。

中断控制与优先级划分是 **Armv7-M** 异常模型不可分割的一部分。它不属于 **Armv7-R** 体系结构，但 **Arm 通用中断控制器**（**Generic Interrupt Controller**，**GIC**）提供与 **Armv7-M** 类似的优先级划分与中断处理模型。在 **Armv7-R** 处理器上使用 **GIC** 可以消除许多异常模型差异。

**Armv7-M** 定义了系统定时器。**Armv7-R** 可以使用类似的定时器，实现也可以把其中断经 **GIC** 路由，以获得最大兼容性。

## 5. 调试支持

两种配置文件都支持**暂停调试**（**Halting debug**）与**监视器调试**（**Monitor debug**）。断点与观察点的处理机制不同。性能剖析的计数器支持级别也不同。两者都支持基于**嵌入式跟踪宏单元**（**Embedded Trace Macrocell**，**ETM**）的可选跟踪特性。**Armv7-M** 的调试支持通常侵入性更低，并作为基本体系结构的一部分提供附加的软件与硬件事件生成跟踪能力。
